# 群数据模型

最后更新：2026-05-07

## 决策：用户目录隔离

**为了谁**：服务于 [群聊协作需求](../requirements/group-collaboration.md)。

**怎么设计**：所有用户数据放在 `~/.march/users/{nickname}/`。初版只需要昵称和头像，不做账号注册。

**为什么这样**：MVP 可以本地优先启动，同时保留未来同步和多用户隔离空间。

## 决策：三库分责

**为了谁**：服务于本地数据清晰维护。

**怎么设计**：

- `user.db`：用户身份、头像、偏好。
- `settings.db`：Provider、模型、Agent 全局池、shadow prompt 变体。
- `groups.db`：群、私聊、群成员、消息、WorkingSummary、执行框架、草稿、闹钟、订阅、hook。

**为什么这样**：账号、全局配置和协作数据生命周期不同，拆开能降低迁移和备份复杂度。

## 决策：群和私聊分表

**为了谁**：服务于群聊和 1v1 两种不同交互。

**怎么设计**：群消息、群成员、群工作空间只服务 group；私聊使用独立 private chat 表，但共享执行框架、记忆、闹钟等底层能力。

**为什么这样**：私聊没有群约束、订阅管理、多 workspace 和激活开关，复用群表会把大量字段变成条件逻辑。

## 决策：Agent 全局配置，群内保存关系

**为了谁**：服务于 Agent 跨群复用。

**怎么设计**：Agent 定义存在 `settings.db`，群成员表保存 `group_id`、`agent_id`、群内启用状态、worktree 状态和最近活动。

**为什么这样**：同一个 Agent 可以服务多个群，但每个群里的运行状态必须独立。
