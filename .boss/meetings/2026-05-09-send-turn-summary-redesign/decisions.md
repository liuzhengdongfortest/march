# 决策记录

日期：2026-05-09

## 决策 1：移除 send_turn_summary 工具，改用后置注入

**决定**：删除 `send_turn_summary` 自定义工具，改为 March 在模型自然结束后注入一段系统提示词，要求模型纯文本输出工作总结。

**原因**：模型不应承担"记得调工具"的责任。March 自己控制总结节奏更可靠、更轻量。

**具体设计**：
- 模型干完活自然结束回复
- March 发送内部提示词（用户不可见）要求模型总结
- 总结轮不暴露任何工具给模型
- 用户看到：一行灰色半透明的 `summarizing...` 动态指示，完成后变为 `summary · done`
- 总结内容不展示给用户，只存入 `[recent_chat]` 供下一轮上下文使用
- token 上限 1k

## 决策 2：总结轮不给工具

**决定**：总结轮不提供任何工具调用能力，模型只能输出纯文本总结。

**原因**：老板明确要求。总结轮只需要文本输出，工具调用在此阶段没有合理场景，反而可能引入意外副作用。

**实现方式**：待定——取决于 Pi SDK 是否支持 per-prompt 工具覆盖。备选方案包括：
- 如果 SDK 支持 prompt 级别工具过滤：只传空工具列表
- 如果不支持：总结提示词中强制声明 "do not call any tools"，并在事件层拦截任何非预期的工具调用
